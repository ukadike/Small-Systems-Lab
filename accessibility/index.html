Accessibility

Accessibility as architecture: a founding constraint across every SSL project, not an add-on.

Baseline requirements

Every SSL branch documents its accessibility baseline against this shared list:

  • keyboard-only operation
  • screen reader compatibility
  • high contrast
  • captions
  • transcripts
  • alt text
  • plain-language summaries
  • multimodal outputs
  • tactile/printable options where possible
  • low-bandwidth and offline-first thinking

Source: docs/accessibility.md.

Navigation accessibility rules

The canonical SSL navigation (see Schema Cards) requires: semantic <nav> elements with clear aria-labels, a visible skip link, real links rather than clickable <div>s, visible focus states, aria-current="page" on the active link, and keyboard-operable mobile menus that expose aria-expanded.

Enforcement layer

Accessible by Design is the audit toolkit that checks websites, PDFs, and p5.js sketches against WCAG 2.2+ rules, and is the enforcement layer referenced by this page. See its rules and schemas.
