Schema Cards

Shared rules, data models, page cards, and reusable structures across SSL projects — infrastructure, not just documentation.

Overview

Schema Cards defines the shared rules and data models that every public SSL page follows: what a page needs to declare about itself, how navigation is structured, and what recurring content types (media, devices, evidence, accessibility checks, canon status) look like once they are formalized. Any recurring pattern across Small Systems Lab, Omoluabi, UMADA, Accessible by Design, or Earth Sensors Lab should eventually become a schema card here.

Page Schema

Canon status: LOCKED

Every public SSL page declares a page schema card: title, project, canonical URL, status, which navigation levels it participates in, and its accessibility checklist. See page.schema.json.

Navigation Rules

Canon status: LOCKED

The rules that govern the canonical global nav, local nav, footer links, and future-page inheritance. See navigation.rules.json.

  • Every public SSL page must include the canonical global navigation.
  • Every public page must be reachable from the global nav, local nav, footer, or site map — no orphan pages.
  • All future public pages inherit the canonical SSL navigation pattern by default.
  • Local navigation only includes pages belonging to the current project or repo.
  • Every public page must have a page schema card and a site map entry.
  • The active navigation item must use aria-current="page".
  • Navigation must be fully usable by keyboard only, with a visible skip link.

Media Schema

Canon status: AWAITING FRAGMENT

Not yet defined. Will describe the shared wrapper for images, audio, and video across SSL projects (alt text, captions, transcripts, provenance).

Device Schema

Canon status: AWAITING FRAGMENT

Not yet defined. Will describe device requirement cards for the Omoluabi physical device and future field instruments (see Omoluabi and Earth Sensors Lab).

Evidence Schema

Canon status: AWAITING FRAGMENT

Not yet defined. Will describe Omoluabi's evidence cards: consent, provenance, and review structure for observations.

Accessibility Schema

Canon status: PROBABLE

Defined in the Accessible by Design repository, which acts as the enforcement layer for accessibility rules across SSL: accessibility-rule.schema.json and audit-result.schema.json. Not yet mirrored here as a page-schema-card-style JSON file — treat the Accessible by Design repo as the source of truth until it is.

Canon Schema

Canon status: EMERGING

UMADA's canon status vocabulary (LOCKED / PROBABLE / EMERGING / OPEN QUESTION / RETIRED / AWAITING FRAGMENT) is documented in prose in UMADA's CANON_STATUS.md. A formal canon.schema.json has not been written yet — this entry is a pointer, not a finished schema.
